===============================================================================
 LOAD-BEARING INVARIANTS  --  breaking one of these is a bug, not a tradeoff
===============================================================================

 [x] 1. The memory block in the system prompt is FROZEN for a session's lifetime.
    Only compaction may ever invalidate the prefix cache.          PLAN §5.2
 [x] 2. The sidecar binds port 0 and requires a token. Never a fixed port.
    It has shell access; the browser must not be able to reach it. PLAN §8
 [x] 3. Memory writes are checked on the BATCH result, and a full store
    returns an actionable error - never a silent truncation.       PLAN §5.3
 [x] 4. Every memory entry passes the security scanner before it is
    accepted. Memory is a persistent injection vector.            PLAN §5.3
 [x] 5. Filesystem tools cannot read or write outside the allowlist.   PLAN §8
 [x] 6. A crash loses at most 250 ms of tokens, and a partial message
    is never presented as a complete one.                         PLAN §7
 [x] 7. `rm cache.db` is always safe and never touches user data.      PLAN §6
 [x] 8. The .md memory files are the human source of truth; on a
    file-vs-DB conflict, the FILE wins.                            PLAN §6
 9. The tool list is closed at eight. Additions cost tokens on
    every single API call.                                        PLAN §4.3
10. Dart types are GENERATED from contracts/. Hand-written DTOs
    are the drift we left Python to avoid.                        PLAN §3
11. A streaming token delta NEVER rebuilds the transcript. It goes
    to that message's ValueNotifier. This is the perf bug we are
    most likely to ship.                                 UI-GUIDELINES §11
12. ONE primitive per concern. A forked button at a call site is
    a bug, not a shortcut.                                UI-GUIDELINES §1
13. No raw color/shadow/radius/duration literal in any widget.
    Everything resolves through the ThemeExtension.      UI-GUIDELINES §13
14. Every surface ships its empty, sparse, dense AND error state.
    Happy-path-only is incomplete.                        UI-GUIDELINES §7
15. Every path resolves through profileRoot(); rows carry
    profile_id. Multi-profile is deferred, not precluded.      PLAN §11.4
16. We NEVER bundle a browser engine for mermaid. System browser
    or honest degradation.                                      PLAN §5.8
17. Mermaid source is untrusted model output: securityLevel
    strict, htmlLabels off, no network, timeout + size cap.     PLAN §5.8
18. stdout belongs to the handshake line ALONE. All logging goes
    to stderr or the app log file.                               PLAN §8
19. EVERY buffer that grows from input off a socket or a pipe has
    a named ceiling in limits.ts/limits.dart -- never an inline
    number, never "big enough". That includes our own sidecar: a
    wedged or downgraded backend is the case a bound is FOR.
    Enforced by app/test/safety_test.dart.                  SAFETY, PLAN §8
20. Wire data is read by a typed reader, never by a cast. A field
    of the wrong type raises WireTypeError NAMING THE FIELD and
    leaves by a designed route; it never crashes an async* body.
    fromJson is generated, so this holds for every contract.
    Enforced by app/test/safety_test.dart.               SAFETY, INVARIANT 10
